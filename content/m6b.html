What makes a capstone convincing

Reviewers and customers are convinced by evidence, not features: a trace that shows where each fact came from, an approval step that cannot be skipped, a gate that fails when quality drops, a monitoring page with real usage, and an honest list of limitations. Your capstone should show all five.

In your job

The twist you choose becomes a demo you can reuse. Pick the one that matches the questions you hear most often from customers, so that the capstone keeps paying off in your presales work after the course.

Which is the best capstone twist?

  1. The most technically impressive one, whatever its use
  2. A small capability linked to a real customer question, with evaluation tasks and a value estimate
  3. A new model trained from scratch

Useful, finished and measured beats impressive and unfinished.

  1. It makes the tool faster
  2. To hide it from the model
  3. Every tool is part of the controlled surface, so changes need review

Step 1: the twist (worked example: EBOM to MBOM differences)

Copy mbom.csv from the data folder into p6-capstone. Add import pandas as pd next to the other imports in bom_server.py, then add this tool above the if __name__ == "__main__": line:



MBOM = pd.read_csv("mbom.csv").fillna("")


@mcp.tool(annotations=READ_ONLY)
def bom_differences(assembly: Annotated[str, Field(description="Optional parent assembly, e.g. E3-1100")] = "") -> dict:
    """Compare the engineering BOM with the manufacturing BOM: parts missing from the MBOM,
    quantity differences, and items that exist only in the MBOM. Optionally for one assembly."""
    e = plmtools.EBOM.groupby(["parent", "part_no"]).qty.sum().rename("ebom_qty")
    m = MBOM.groupby(["parent", "part_no"]).qty.sum().rename("mbom_qty")
    both = pd.concat([e, m], axis=1).reset_index()
    if assembly:
        both = both[both.parent == assembly.strip().upper()]

    def rows(df):
        return [{k: (int(v) if isinstance(v, float) and v == v else (None if v != v else v))
                 for k, v in r.items()} for r in df.to_dict("records")]

    return {"missing_in_mbom": rows(both[both.mbom_qty.isna()]),
            "only_in_mbom": rows(both[both.ebom_qty.isna()]),
            "quantity_differences": rows(both[both.ebom_qty.notna() & both.mbom_qty.notna()
                                              & (both.ebom_qty != both.mbom_qty)])}

Step 3: the release gate

%%writefile gate.py
"""Release gate: run the evaluation through the capstone agent and fail if a threshold is missed.
Run before every deployment: python gate.py"""
import asyncio
import datetime
import json
import os
import re
import sys
import pandas as pd
import capstone_agent as ca

THRESHOLDS = {"task_success": 0.75, "grounded": 0.9, "mean_seconds": 30.0}


def has_all(text, must):
    text = text.lower()
    return all(any(alt.lower() in text for alt in item.split("|")) for item in must)


def grounded(answer, trace):
    """Every number of 3 or more digits in the answer appears in some tool result."""
    results = " ".join(t["result"] for t in trace).replace(",", "")
    nums = [n.replace(",", "") for n in re.findall(r"\d[\d,]*(?:\.\d+)?", answer)]
    return all(n in results for n in nums if len(n) >= 3)


async def main():
    rows = []
    for t in json.load(open("capstone_eval.json")):
        out = await ca.ask(t["question"])
        text = out["answer"] + " " + json.dumps(out["pending"])
        rows.append({"id": t["id"],
                     "success": has_all(text, t["must"]) and bool(out["pending"]) == t.get("expects_draft", False),
                     "grounded": grounded(out["answer"], out["trace"]),
                     "steps": out["steps"], "tokens": out["tokens"], "seconds": out["seconds"]})
    df = pd.DataFrame(rows)
    print(df.to_string(index=False))
    summary = {"time": datetime.datetime.now().isoformat(timespec="seconds"), "model": ca.CHAT_MODEL,
               "task_success": round(float(df.success.mean()), 3), "grounded": round(float(df.grounded.mean()), 3),
               "mean_seconds": round(float(df.seconds.mean()), 1), "mean_tokens": round(float(df.tokens.mean()))}
    pd.DataFrame([summary]).to_csv("eval_history.csv", mode="a", index=False,
                                   header=not os.path.exists("eval_history.csv"))
    failed = [k for k in ("task_success", "grounded") if summary[k] < THRESHOLDS[k]]
    if summary["mean_seconds"] > THRESHOLDS["mean_seconds"]:
        failed.append("mean_seconds")
    print("\n", summary)
    if failed:
        print("GATE FAILED on:", failed)
        sys.exit(1)
    print("GATE PASSED")


asyncio.run(main())
!python gate.py

The gate runs every task through the real agent and servers, checks required facts, checks that the draft task produced a pending action and the others did not, checks that every number of three or more digits in an answer appears in a tool result, and appends a summary to eval_history.csv. It exits with an error if a threshold is missed. Run it on your local model and on the hosted model, and keep both rows in the history.

"""Capstone web app: chat with the Sahyadri engineering assistant, approve drafts, give feedback."""
import asyncio
import json
import streamlit as st
import capstone_agent as ca

st.set_page_config(page_title="Sahyadri engineering assistant", layout="wide")
st.title("Sahyadri engineering assistant")
st.caption("Capstone demo on synthetic data. Answers come from MCP servers over the part master, "
           "BOM, engineering changes and controlled documents. Draft actions need your approval.")

if "turns" not in st.session_state:
    st.session_state.turns = []

for i, t in enumerate(st.session_state.turns):
    st.chat_message("user").markdown(t["question"])
    with st.chat_message("assistant"):
        st.markdown(t["answer"])
        with st.expander(f'Trace: {len(t["trace"])} tool calls, {t["tokens"]} tokens, {t["seconds"]} s'):
            for s in t["trace"]:
                st.code(f'{s["tool"]}({json.dumps(s["args"])})\n-> {s["result"][:300]}')
        for j, action in enumerate(t["pending"]):
            key = f"{i}-{j}"
            st.info(f'Proposed action: {action["tool"]} {json.dumps(action["args"])}')
            if key in st.session_state.get("done", {}):
                st.success(st.session_state.done[key])
            elif st.button("Approve and create the draft", key=f"approve-{key}"):
                result = asyncio.run(ca.approve(action, approver="demo user"))
                st.session_state.setdefault("done", {})[key] = "Draft created. " + result[:200]
                st.rerun()
        up, down, _ = st.columns([1, 1, 10])
        if up.button("👍", key=f"up-{i}"):
            ca.log_usage({"event": "feedback", "question": t["question"], "score": 1})
            st.toast("Thanks for the feedback")
        if down.button("👎", key=f"down-{i}"):
            ca.log_usage({"event": "feedback", "question": t["question"], "score": -1})
            st.toast("Thanks. This question will be reviewed.")

if question := st.chat_input("Ask about parts, BOMs, changes or standards"):
    with st.spinner("Working through the tools..."):
        st.session_state.turns.append(asyncio.run(ca.ask(question)))
    st.rerun()

Pending actions appear with an approval button; nothing is drafted until someone clicks it, and the approval is logged. Every answer has a trace and feedback buttons. In a company deployment, the approver's name would come from the user's sign-in rather than "demo user".

In presales, you often play a mix of product owner and solution architect. Knowing the whole cast lets you ask, early, "who will play each role at your company?", a question that predicts success better than any technical one.

Operating models

  • Centralised: one AI team builds everything. Consistent, but becomes a bottleneck.
  • Decentralised: each department builds its own. Fast, but duplicates work and controls (Unit 18's connector sprawl).
  • Hub and spoke: a central team (a centre of excellence) owns the platform, shared MCP servers, evaluation tooling, security patterns and governance; departments build use cases on top with their own owners. Most companies that scale end up here.

Governance without paralysis

Frameworks give a shared language: the NIST AI Risk Management Framework (govern, map, measure, manage), ISO/IEC 42001 (an AI management system standard that can be certified, structured like ISO 9001), and the EU AI Act (obligations by risk category; relevant to Indian companies selling into Europe). Most engineering assistants that draft and inform, with human approval, sit in lower-risk categories; AI that is part of a product's safety function or makes decisions about people sits higher. Practical governance means a register of AI use cases with owners and risk levels, standard controls by risk level, and a light review before each stage gate. You have built most of those controls in this course.

Adoption is designed

  • Put the assistant where the work is: inside the PLM, the change form, the shift handover.
  • Recruit champions in each team and give them early access and a voice in the evaluation set.
  • Train on judgement, not buttons: what to ask, how to read citations and traces, when not to trust an answer.
  • Measure weekly active use and act on it; adoption that falls after month two needs investigation, not more features.
  • Change incentives where needed: if engineers are measured on hours booked, time saved can feel like a threat.
