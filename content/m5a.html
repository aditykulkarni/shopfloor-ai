In Part 4 your agent called Python functions you imported. That works for one agent and one data set. A company has many AI applications and many systems. The Model Context Protocol (MCP) is the open standard for connecting the two, and it is quickly becoming how enterprise software is made usable by AI.

The integration problem

Suppose a company has 4 AI applications (a chat assistant, a coding assistant, a document copilot and a change agent) and 5 systems (PLM, ERP, MES, document management, quality). Connecting each application to each system means up to 4 × 5 = 20 custom integrations, each built and maintained separately. Add one application and you build 5 more.

MCP turns this into 4 + 5: each system gets one MCP server, each application includes an MCP client, and any client can use any server. It is often compared to USB: one standard port instead of a different cable for every device.

The parts

PartWhat it isExample
HostThe AI application the user works inClaude Desktop, an IDE, your own Streamlit app or agent
ClientThe connector inside the host; one per serverThe code in your agent that talks to the BOM server
ServerA program that exposes a system's capabilities in the MCP formatYour bom_server.py over the part master and BOM

What a server offers: three primitives

  • Tools: functions the model can call, such as where_used. Exactly what you built in Part 4, now with a standard description format. Tools carry annotations such as "read only" or "destructive", which hosts use to decide when to ask the user for approval.
  • Resources: data the application can read and put in context, addressed by a URI such as plm://parts/E3-2400 or doc://DS-FAST-001. Resources are usually chosen by the application or user, while tools are chosen by the model.
  • Prompts: reusable templates the server offers to users, such as "impact review for change X". They package a company's best way of doing a task.

The protocol also lets servers ask the host for things: elicitation (ask the user a question, for example to confirm an action) and sampling (ask the host's model to generate text). You will meet them, but tools, resources and prompts are what matter most.

How they talk

Messages are JSON-RPC: small JSON requests and responses such as tools/list and tools/call. Two transports carry them:

  • stdio: the host starts the server as a local program and talks through its standard input and output. Simple, local, ideal for development and desktop tools.
  • Streamable HTTP: the server runs as a web service that many users and hosts reach over the network. This is how enterprise servers are deployed, with authentication (OAuth) in front.

Why it matters to you

MCP was published by Anthropic in late 2024 and has since been adopted widely across AI vendors, developer tools and enterprise software, and is now governed as an open project. For PLM and manufacturing this changes the question customers ask. It is no longer only "which AI does your platform have?" but also "can the AI tools we already chose use our engineering data, safely?" An MCP server over PLM data, with the platform's access rights and lifecycle rules enforced inside it, is an answer to that question.

What MCP does not do

MCP is plumbing. It does not make a model accurate, it does not decide which actions are safe, and it does not secure a badly designed server. Everything from Part 4 still applies: good tool design, gates for writes, least privilege and logs. Unit 21 covers MCP's own security issues.

%%writefile bom_server.py
"""MCP server: read-only access to the Sahyadri part master and E3 BOM."""
import os
os.chdir(os.path.dirname(os.path.abspath(__file__)))   # find the CSV files wherever the host starts us

from typing import Annotated
from pydantic import Field
from mcp.server.mcpserver import MCPServer
from mcp.types import ToolAnnotations
import plmtools

mcp = MCPServer("sahyadri-bom",
                instructions="Read-only access to the Sahyadri E3 part master and engineering BOM.")
READ_ONLY = ToolAnnotations(readOnlyHint=True, openWorldHint=False)
PartNo = Annotated[str, Field(description="Part number, for example E3-2400")]


@mcp.tool(annotations=READ_ONLY)
def search_parts(text: Annotated[str, Field(description="Words from the part description")]) -> list[dict]:
    """Find part numbers from a description such as 'windshield glass'. Use first when no number is given."""
    return plmtools.search_parts(text)


@mcp.tool(annotations=READ_ONLY)
def get_part(part_no: PartNo) -> dict:
    """Part master record: revision, lifecycle, make or buy, material, mass, cost, supplier, stock."""
    return plmtools.get_part(part_no)


@mcp.tool(annotations=READ_ONLY)
def where_used(part_no: PartNo) -> list[dict]:
    """Assemblies that directly contain a part, with quantity per assembly. Use for impact questions."""
    return plmtools.where_used(part_no)


if __name__ == "__main__":
    mcp.run()   # stdio transport by default

Compare this with Part 4. The functions are the same; the decorator turns each into an MCP tool. The SDK builds the JSON schema from the type hints, takes the description from the docstring and adds parameter descriptions from Field. The annotation tells hosts these tools only read.

Step 4: a Python client

%%writefile try_bom.py
"""Connect to the BOM server over stdio, list its tools and call two of them."""
import asyncio
import json
import sys
from mcp import Client, StdioServerParameters


def text_of(result):
    if result.structured_content is not None:
        return json.dumps(result.structured_content)
    return "\n".join(c.text for c in result.content if hasattr(c, "text"))


async def main():
    server = StdioServerParameters(command=sys.executable, args=["bom_server.py"])
    async with Client(server) as client:
        tools = (await client.list_tools()).tools
        for t in tools:
            print(f"{t.name}: read_only={t.annotations.read_only_hint}  {t.description[:60]}")
        for name, args in [("search_parts", {"text": "windshield glass"}),
                           ("where_used", {"part_no": "E3-9001"})]:
            r = await client.call_tool(name, args)
            print(f"\n{name}({args}) error={r.is_error}\n{text_of(r)[:300]}")


asyncio.run(main())

A server is a product with users: models, applications and the engineers behind them. This session covers how to cut servers, which primitive to use for what, and how to make tools that models use well.

Cut servers by domain and by risk

One giant "PLM server" with 60 tools confuses models and makes permissions coarse. One server per table is too fine. A good cut follows business domains and their owners, with risk as a second axis:

ServerDomainTypical toolsRisk
sahyadri-bomParts and product structuresearch_parts, get_part, where_used, qty_per_vehicle, stock_exposureRead only
sahyadri-changesEngineering changelist_changes, get_change, draft_change_requestReads, plus one draft action
sahyadri-docsControlled documentssearch_docs, plus each document as a resourceRead only, access-filtered

A host can then connect a read-only assistant to the first and third, and only the change agent to the second.

Tools, resources or prompts?

  • Use a tool when the model should decide to fetch or do something during a task, with parameters: "where is this part used?"
  • Use a resource for a thing with an address that a user or application might attach as context: a document, a part record, a BOM. Resource templates such as doc://{doc_id} make a whole collection addressable.
  • Use a prompt to ship the company's way of doing a task: "impact review for change X" with the right checklist. Prompts are how process knowledge travels with the server.

Tool design, revisited for MCP

  • Write for the model. Descriptions say when to use the tool and how it relates to others ("use search_parts first if you have no part number").
  • Return what a reader needs, not everything. Ten relevant fields, not the 120 columns of the PLM table. Paginate long lists.
  • Validate inputs. Check part number formats and return a helpful error, so the model can correct itself.
  • Annotate honestly. readOnlyHint, destructiveHint, idempotentHint (repeating the call has no further effect) and openWorldHint (the tool reaches outside systems) help hosts decide when to ask the user.
  • Prefer drafts to writes. draft_change_request creates a draft that a person submits in the PLM; it does not release anything.

Test servers like any software

The Python SDK can connect a client to a server object in the same process, with no subprocess. That makes automated tests fast: list the tools, check their schemas and annotations, call each with good and bad inputs, and assert on the results. Run the tests on every change. A server many AI applications depend on deserves a test suite.

    """Stock at Chakan, its value in rupees, and months of production it covers."""
    return plmtools.stock_exposure(part_no)


@mcp.resource("plm://parts/{part_no}", mime_type="application/json")
def part_record(part_no: str) -> str:
    """The part master record as JSON."""
    return json.dumps(plmtools.get_part(part_no), default=str)

    mcp.run()

The pattern on PartNo makes the SDK reject malformed input before your code runs, and the pattern appears in the schema, so the model sees the expected format.

Step 2: the changes server, with a draft action and a prompt

%%writefile changes_server.py
"""MCP server: engineering changes. Reads, plus creating drafts that people submit in the PLM."""
import datetime
import json
import os
os.chdir(os.path.dirname(os.path.abspath(__file__)))

from typing import Annotated
from pydantic import Field
from mcp.server.mcpserver import MCPServer
from mcp.types import ToolAnnotations
import plmtools

mcp = MCPServer("sahyadri-changes",
                instructions="Engineering changes for the E3 platform. You can read changes and create "
                             "draft change requests. Drafts are reviewed and submitted by people in the PLM.")
READ_ONLY = ToolAnnotations(readOnlyHint=True, idempotentHint=True, openWorldHint=False)
DRAFT = ToolAnnotations(readOnlyHint=False, destructiveHint=False, idempotentHint=False, openWorldHint=False)
DOCS = {d["id"]: d for d in json.load(open("docs.json"))}


@mcp.tool(annotations=READ_ONLY)
def list_changes(part_no: Annotated[str, Field(description="Optional part number filter")] = "",
                 status: Annotated[str, Field(description="Optional: new, draft, in review or released")] = "") -> list[dict]:
    """List engineering changes (ECN and ECR), optionally for one part or status."""
    return plmtools.list_changes(part_no, status)


@mcp.tool(annotations=READ_ONLY)
def get_change(change_id: Annotated[str, Field(description="For example ECN-2026-0139")]) -> dict:
    """One change with its record and, if released as a notice, the notice text."""
    rows = [c for c in plmtools.list_changes() if c["change_id"] == change_id.strip().upper()]
    if not rows:
        return {"error": f"No change {change_id}. Use list_changes to see the IDs."}
    notice = DOCS.get(rows[0]["change_id"])
    return {**rows[0], "notice_text": notice["text"] if notice else None}


@mcp.tool(annotations=DRAFT)
def draft_change_request(title: Annotated[str, Field(max_length=120)],
                         part_numbers: Annotated[list[str], Field(min_length=1, max_length=20)],
                         reason: Annotated[str, Field(max_length=1000)]) -> dict:
    """Create a DRAFT change request for a person to review and submit in the PLM. Nothing is released."""
    unknown = [p for p in part_numbers if "error" in plmtools.get_part(p)]
    if unknown:
        return {"error": f"Unknown part numbers: {unknown}. Check them with the BOM server first."}
    os.makedirs("drafts", exist_ok=True)
    draft = {"draft_id": "DRAFT-" + datetime.datetime.now().strftime("%Y%m%d-%H%M%S"),
             "title": title, "part_numbers": part_numbers, "reason": reason, "status": "draft"}
    with open("drafts/change_requests.jsonl", "a") as f:
        f.write(json.dumps(draft) + "\n")
    return draft


@mcp.prompt()
def impact_review(change_id: str) -> str:
    """Sahyadri's standard checklist for a change impact review."""
    return (f"Prepare an impact review for {change_id}. Use get_change first. For every affected part: "
            "where_used, qty_per_vehicle, stock_exposure and open changes. Search the documents for the change "
            "procedure and any standard that applies. List what could not be checked. Do not decide the change "
            "class; list the facts the change control board needs.")


if __name__ == "__main__":
    mcp.run()

Step 3: the documents server, with resources

%%writefile docs_server.py
"""MCP server: search and read Sahyadri controlled documents (current revisions only)."""
import json
import os
os.chdir(os.path.dirname(os.path.abspath(__file__)))

from typing import Annotated
from pydantic import Field
from mcp.server.mcpserver import MCPServer
from mcp.types import ToolAnnotations
from docindex import build_index, get_index, search

mcp = MCPServer("sahyadri-docs",
                instructions="Search and read Sahyadri controlled documents. Superseded revisions are excluded. "
                             "Always cite the document ID and revision.")
READ_ONLY = ToolAnnotations(readOnlyHint=True, idempotentHint=True, openWorldHint=False)
DOCS = {d["id"]: d for d in json.load(open("docs.json")) if d["status"] != "superseded"}
try:
    COL = get_index()
except Exception:
    COL = build_index()


@mcp.tool(annotations=READ_ONLY)
def search_docs(query: Annotated[str, Field(description="What to look for, in plain words")],
                k: Annotated[int, Field(ge=1, le=8)] = 4) -> list[dict]:
    """Search standards, procedures, work instructions, change notices and test reports."""
    return [{"doc_id": h["doc_id"], "rev": h["rev"], "status": h["status"], "title": h["title"],
             "text": h["text"][:800]} for h in search(COL, query, k=k)]


@mcp.resource("doc://{doc_id}", mime_type="text/markdown")
def document(doc_id: str) -> str:
    """The full text of one current document."""
    d = DOCS.get(doc_id.upper())
    if not d:
        return f"No current document {doc_id}."
    return f"# {d['id']}: {d['title']}\nRevision {d['rev']}, {d['status']}, {d['date']}\n\n{d['text']}"


if __name__ == "__main__":
    mcp.run()

Step 4: an automated test suite

%%writefile test_servers.py
"""Tests for the three Sahyadri MCP servers. Run: python test_servers.py"""
import asyncio
import json
import sys
from mcp import Client
import bom_server, changes_server, docs_server

failures = []


def check(name, condition):
    print(("PASS " if condition else "FAIL ") + name)
    if not condition:
        failures.append(name)


def text_of(r):
    if r.structured_content is not None:
        return json.dumps(r.structured_content)
    return "\n".join(c.text for c in r.content if hasattr(c, "text"))


async def test_bom():
    async with Client(bom_server.mcp) as c:
        tools = {t.name: t for t in (await c.list_tools()).tools}
        check("bom: five tools", len(tools) == 5)
        check("bom: all read only", all(t.annotations.read_only_hint for t in tools.values()))
        r = await c.call_tool("qty_per_vehicle", {"part_no": "E3-9001"})
        check("bom: 24 bolts per vehicle", '"qty_per_vehicle": 24' in text_of(r))
        r = await c.call_tool("get_part", {"part_no": "E3-999"})
        check("bom: unknown part gives a helpful error", "No part" in text_of(r))
        r = await c.call_tool("get_part", {"part_no": "DROP TABLE parts;"})
        check("bom: malformed part number rejected", r.is_error)
        res = await c.read_resource("plm://parts/E3-4200")
        check("bom: part resource", "ClearView" in res.contents[0].text)


async def test_changes():
    async with Client(changes_server.mcp) as c:
        tools = {t.name: t for t in (await c.list_tools()).tools}
        check("changes: draft tool is not read only", not tools["draft_change_request"].annotations.read_only_hint)
        check("changes: draft tool is not destructive", tools["draft_change_request"].annotations.destructive_hint is False)
        r = await c.call_tool("get_change", {"change_id": "ECN-2026-0139"})
        check("changes: notice text included", "fatigue" in text_of(r))
        r = await c.call_tool("draft_change_request", {"title": "Test", "part_numbers": ["E3-0001"], "reason": "x"})
        check("changes: draft refuses unknown parts", "Unknown part" in text_of(r))
        prompts = (await c.list_prompts()).prompts
        check("changes: impact_review prompt", any(p.name == "impact_review" for p in prompts))


async def test_docs():
    async with Client(docs_server.mcp) as c:
        r = await c.call_tool("search_docs", {"query": "torque wrench calibration interval", "k": 8})
        check("docs: superseded revision excluded", "DS-FAST-001-B" not in text_of(r))
        res = await c.read_resource("doc://DS-FAST-001")
        check("docs: document resource", "45 Nm" in res.contents[0].text)
        res = await c.read_resource("doc://DS-FAST-001-B")
        check("docs: superseded document not readable", "No current document" in res.contents[0].text)


async def main():
    await test_bom()
    await test_changes()
    await test_docs()

Which is the best reason to expose a checklist as an MCP prompt?

  1. Prompts are cheaper than tools
  2. Models cannot read checklists otherwise
  3. It ships the company's way of doing a task to every host that uses the server
  4. Prompts run automatically

Prompts carry process knowledge.

A tool returns all 120 PLM columns for a part. The main problem is:

  1. It wastes context and buries the fields the model needs
  2. MCP forbids it
  3. It is too fast
  4. Nothing

Return what a reader needs.

Which annotation fits draft_change_request?

  1. readOnlyHint=True
  2. destructiveHint=True
  3. openWorldHint=True
  4. readOnlyHint=False, destructiveHint=False

It creates something, but destroys nothing.

Where should part-number validation live?

  1. Only in the model's prompt

  3. In the host's user interface
  4. Nowhere
